# 设计师追踪日志

## 阶段一：资产规划

### 主体类型与简报触点
主体类型：organization；主体名称：上海创智学院。简报第11章已按优先级列出触点，本轮映射如下：
- 首要：招生营与博士遴选主视觉/模板、科研成果发布会视觉系统、官网与科研新闻版式组件、学术报告/创智日历海报模板。
- 可选：全球青年教师招聘视觉、空间导视与楼层标识。
- 本轮不做：文创周边、传统招生折页大礼包。

### 视觉方向决策
- 所选方向：`research-signal`（RUNSTACK OS / 运行栈操作系统）
- 考虑过的备选方向：`product-interface`、`campaign-energy`、`editorial-authority`
- 选择原因：用户明确要求以方向一“RUNSTACK OS / 运行栈操作系统”为起点；该方向最直接承接简报第5章“全栈科研系统、任务流、节点拓扑、堆栈卡片、科研驾驶舱”，并能覆盖第11章的招生遴选、科研成果发布、官网新闻和学术日历。
- 使用的视觉研究：direction-options.md 推荐RUNSTACK OS；采用深色优先、智能蓝关键节点、12列技术网格、堆栈视图、任务卡/成果卡、状态条和“排队—运行—验证—发布”的运行状态逻辑。visual-references.md 中参考 OpenAI 的克制留白、MIT 的统一系统、IBM Carbon 的技术图表严谨性、Linear 的运行态界面秩序。
- 规避的默认套路：教育招生包、传统高校院徽包、校园摄影宣传包、泛AI蓝紫粒子包、企业SaaS后台大屏包、为每个活动单独换皮的彩虹活动品牌。

### 交付策略决策
- 所选策略：`digital-system`
- 选择原因：第11章四个首要触点均有强数字传播属性：官网/科研新闻是官方入口，招生遴选依赖线上通知与报名系统，科研成果发布需要线上解释图与社媒传播，学术活动需要可快速迭代的数字卡片。
- 其他策略被排除或推迟的原因：`identity-core`被推迟，因为现有官网已有中英文组合标识，本轮不重新造标；`campaign-system`被收束，因为不希望为招生、科研、讲座分别做独立活动包；`spatial-system`被推迟，因为空间导视在简报中为可选；`publishing-system`仅作为后续报告/论文发布延展，不进入本轮；`community-system`与文创周边被明确列为本轮不做。

### 最终4-8个资产的整体逻辑
最终选择6个资产，全部围绕`digital-system`：官网首屏、招生流程、科研解释图、新闻卡片、活动社交卡、数字通知页头。它们共同使用RUNSTACK OS的堆栈、任务流、状态条、细线网格和智能蓝强调色；省略color-palette、campus、admissions brochure、merchandise等默认项，是为了避免把上海创智学院误读为普通学校VI或活动周边包。
