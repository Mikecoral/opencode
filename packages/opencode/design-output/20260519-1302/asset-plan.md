# 资产生成计划

## 决策依据
本次以用户认可的 **GRID-ENGINE / 全栈算力引擎** 为起点，将其归入 `research-signal` 视觉方向：简报第5章明确指出“AI 基础设施与算力集群”“科研驾驶舱与全栈引擎”“模块化引擎图谱 / 可生长系统图”是最核心的视觉 DNA。第11章中“官网首页与科研项目卡片系统”为首要触点，且 GRID-ENGINE 在方向选项中被推荐为最适合承接主标识、项目子符号、官网卡片、科研成果与平台 UI 的系统，因此本轮交付聚焦数字传播与科研界面资产，而不是传统学院招生包。

## 视觉方向
- 所选方向：`research-signal`（执行语汇：`GRID-ENGINE / 全栈算力引擎`）
- 原因：方向选项明确推荐 GRID-ENGINE，因其最贴合简报中的“算力集群、科研驾驶舱、全栈引擎、模块化 monogram、项目子符号”；视觉研究也指出应借鉴 MIT Media Lab 的底层规则生成系统和 IBM 的中性色信息层，而非泛化科技线条。
- 规避了什么：规避“传统学院盾牌/书本/橄榄枝”“校园红蓝招生视觉”“满屏赛博 HUD/随机粒子/蓝紫大渐变”，也不把学院处理成地产化玻璃楼宣传或 OpenAI 式过度中性极简。

## 交付策略
- 所选策略：`digital-system`
- 原因：第11章首要触点中，“官网首页与科研项目卡片系统”最能把 GRID-ENGINE 的网格、节点、项目 glyph、状态标签和科研驾驶舱语言系统化；同时该数字系统可向科研成果发布、招生营信息和人才招募页面延展。为避免混入活动主视觉或完整 VI 手册，本轮只生成数字系统中的可复用模式。

## 触点优先级
| 触点 | 优先级 | 简报依据 | 决策 |
|------|--------|---------|------|
| 官网首页与科研项目卡片系统 | 首要 | 官网承担“走进创智、招生培养、科研创新、人事人才”聚合入口，需要统一项目卡、导师卡、新闻卡、日历卡 | 包含：作为数字系统核心，生成 web-hero、project-card-system、dashboard-widget-system |
| 科研成果发布会主视觉与报告模板 | 首要 | “创奇·智能新引擎”七大成果需要系列化成果图谱、发布屏幕、报告封面 | 部分包含：仅纳入数字化成果模块与仪表盘视觉，不生成独立发布会海报或报告封面 |
| 招生营/博士遴选视觉系统 | 首要 | 博士营、夏令营、代码机考、48 小时课题实训是核心学生获取场景 | 部分包含：纳入 social-card-template 的可复用招募/通知样式，不做具体营地海报 |
| 导师/人才招募视觉与招聘页资产 | 首要 | “Calling for Marvellers”与人事入口说明人才招募需要从岗位招聘升级为共创号召 | 部分包含：通过 email-header 与社交卡片模板支持数字招募触点，不做单独招聘长图 |
| 空间导视与楼宇欢迎屏 | 可选 | 玻璃幕墙与 AI 小镇空间可强化体验，但需先确认线下改造权限 | 推迟：属于 `spatial-system`，本轮不混入 |
| 开源项目 / 数据集 / 平台产品标识 | 可选 | 数据工厂、TaaS 等未来可能需要产品化子品牌体系 | 推迟：可由 project-glyph-system 预留规则，但不生成具体产品子品牌 |
| 社交媒体海报模板 | 可选 | “视觉创智”已有多类传播内容，社媒模板有助连续传播但不是第一轮最核心 | 包含：生成通用 social-card-template，作为数字系统延展 |
| 通用文创周边 | 本轮不做 | 缺少当前品牌问题证据，优先级低于招生、科研发布、官网与人才招募 | 排除：会导致输出泛化为学院周边包 |

## 考虑的资产
| 资产创意 | 决策 | 原因 |
|---------|------|------|
| logo-primary | 包含 | 必须的形象锚点；需在现有“竖向图形 + 中英文字标”结构基础上探索模块化 SII / 创 / C-Z monogram |
| web-hero | 包含 | 服务首要触点“官网首页”，展示 GRID-ENGINE 的品牌首屏语言：深色科研系统、节点链路、项目入口和中英品牌名 |
| project-card-system | 包含 | 服务官网科研项目、导师/新闻/日历卡片系统；把“AI Infra、数据工厂、科研驾驶舱”等转译为可复用卡片规则 |
| dashboard-widget-system | 包含 | 承接“科研驾驶舱与全栈引擎”，表现状态标签、算力指标、任务队列、成果模块等数字界面组件 |
| project-glyph-system | 包含 | 从主标识网格派生子 glyph，为未来项目卡片、开源平台和成果模块预留统一符号规则 |
| social-card-template | 包含 | 支持招生营、科研发布、人才招募的数字传播，但保持通用模板，不绑定某一次活动 |
| email-header | 包含 | 服务人事人才、博士遴选、成果通知等数字触点，形成官网外的轻量信息入口 |
| admissions-poster | 排除 | 虽然招生营为首要触点，但海报属于 `campaign-system`；本轮不做具体活动 KV，避免回到“学校=招生海报”默认包 |
| report-cover | 排除 | 科研成果报告重要，但报告封面属于 `publishing-system`；本轮只保留可在官网/仪表盘中复用的成果模块语言 |
| entrance-signage | 排除 | 空间导视为可选触点且需线下权限确认，属于 `spatial-system`，与本轮 digital-system 不一致 |
| merchandise-mockup | 排除 | 通用文创周边被简报列为本轮不做，且无法回答当前数字系统策略中的具体功能 |

## 自检
- 本计划是否规避了可预测的行业默认包？是。未按“学校=招生+校园+宣传册+周边”组合出资产，而是从 GRID-ENGINE 与官网/科研界面触点推导数字系统。
- 所有非Logo资产是否都关联到首要触点或所选策略？是。web-hero、project-card-system、dashboard-widget-system 直接服务官网与科研驾驶舱；social-card-template、email-header 服务招生/成果/人才招募的数字化延展；project-glyph-system 支撑项目卡片与未来平台入口。
- 是否避免了默认添加 color-palette/campus/admissions/brochure/merchandise？是。未生成独立 color-palette、校园图、招生海报、宣传册或文创周边；招生只作为通用数字模板的内容场景被承接。
- 整套资产是否像一个连贯系统而非互不相关的样品？是。资产从主标识网格出发，向官网首屏、项目卡、驾驶舱组件、子 glyph、社交与邮件模板逐层扩展，统一于深色科研信息界面、节点链路、等宽标签和单一荧青高亮纪律。
